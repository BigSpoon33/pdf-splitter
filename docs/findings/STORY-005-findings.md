## Gate r1 fixes (`4006eff`, review: `docs/findings/STORY-005-review.md`)
Three confirmed findings, fixed forward in one commit. Review finding 2 (500s carry a request id) was refuted as a STORY-005 defect and is STORY-007's AC-7; nothing for it was built here.

1. **Redaction that can't be dodged** (finding 1). `access_log.redact_path` (`access_log.py:25`) no longer anchors on `^/api/jobs/`. It replaces every token shaped like `new_job_id()` output, `[A-Za-z0-9_-]{22}` bounded by non-token characters, wherever it sits in the path, so `//api/jobs/<id>`, `/api/jobs//<id>`, `/api//jobs/<id>`, `/API/jobs/<id>`, `/api/jobs/./<id>`, `/api/jobs/../jobs/<id>`, the absolute form `http://h:1/api/jobs/<id>`, `<id>.json` and `<id>;v=1` all log `log_id(id)`. Deliberately a token match, not a segment match, so an extension or a `;` parameter glued to the id can't hide it either; 21- or 23-char runs and runs with other characters are left alone (the SPA's hashed asset names contain a `.`). The middleware reads `request.scope["path"]` (decoded once, the string the router matched on) rather than `request.url.path`, which decodes a second time. Contracts: `tests/test_upload.py::test_redact_path`, `::test_redact_path_cannot_be_dodged_by_path_shape` (12 shapes × a fixed dash-leading id and a fresh `new_job_id()`).
2. **Log paths escaped** (finding 3). `access_log.loggable_path` (`access_log.py:29`) percent-encodes the redacted path with `urllib.parse.quote(..., safe="/:@!$&'()*+,;=-._~")` (the RFC 3986 path characters). The ASGI path is percent-decoded client input, so `%1B%5B31m` had become a real ESC and `%E2%80%A8` a real U+2028 by the time it was logged; they are now logged as `%1B%5B31m` and `%E2%80%A8`, a literal `%` as `%25`, and every access line is ASCII and printable. Contract: `::test_logged_path_is_escaped` (through the TestClient, which delivers the decoded bytes exactly like uvicorn).
3. **Preflight argv hardened** (finding 4). `Settings.jobs_dir` has an after-validator that `resolve()`s it (`config.py:27`), so `PDFSPLIT_JOBS_DIR=.` or empty gives `Path.cwd()`, and `db_path` is absolute too; the default `jobs` therefore reads back as `<cwd>/jobs` (`tests/test_config.py::test_defaults` was updated). Independently, `run_preflight` puts `--` before the path (`upload.py:74`), so an id starting with `-` (1 in 64) can never parse as an option even if a future caller passes a relative path. Contracts: `tests/test_config.py::test_jobs_dir_is_always_absolute`, `tests/test_upload.py::test_upload_with_relative_jobs_dir_and_dash_id` (chdir to tmp, `jobs_dir=Path(".")`, forced ids `-bCd…` and `--Cd…` → 201 + `source.pdf` + rows), `::test_preflight_main_accepts_a_dash_leading_path` (and shows argparse rejects it without `--`), and `::test_preflight_uses_a_10s_timeout_and_this_interpreter` now asserts `cmd[-2] == "--"` and an absolute `cmd[-1]`.

Re-verified live on port 8012 (server stopped by PID): the reviewer's seven path shapes plus `%1B%5B31m`, `%E2%80%A8%C2%85<id>%0A` and `%25`, sent as raw HTTP request targets, all logged `GET … /23962981 404` (the hash of the dash id) with zero raw ids, zero ESC bytes and zero non-ASCII bytes in the log; the reviewer's `dash.py` now prints `dash-id 201` and `normal-id 201`.

## Bugs Found
- **PyMuPDF 1.28.2 prints a `fitz` deprecation notice to STDOUT** (`warning: The \`fitz\` API is deprecated…`) when anything runs `import fitz`. That broke a "stdout is one JSON object" contract on the first run. Fixed two ways: `preflight.py` imports `pymupdf`, and `run_preflight` parses only the last stdout line. The kickoff's `import fitz` advice is outdated for this pin, and any subprocess protocol in STORY-006 should use the same last-line rule.

## Decisions (small ambiguities resolved)
- **Error body:** `{"code": str, "message": str}` (`upload.py:67` `reject`, messages in `upload.MESSAGES`). 413 for `too_large`/`too_many_pages`, and 400 for everything else. The body never includes a path or the id. `tests/test_upload.py::assert_rejected` is the contract.
- **`unreadable` is a new code.** Architecture § api/§ Interfaces list `not_pdf|encrypted|no_text_layer` for 400; the story adds `unreadable` (a crash or timeout). Architecture should add it (doc gap, not changed here).
- **Missing or empty file:** 400 `not_pdf` instead of FastAPI's 422 `{"detail"}`, so every upload rejection has the same shape.
- **Size cap timing:** FastAPI/Starlette parse the multipart body (spooling to a temp file after 1 MB) *before* the handler runs, so `too_large` is decided while copying from that spool, not while the bytes arrive. Memory use stays bounded (the story accepts this); the 210 MB network cap is Caddy's (STORY-013). A real early abort would need a raw `request.stream()` parser, which is only worth building if disk-spool abuse shows up.
- **`--max-pages` is passed to the preflight**, so a 50 000-page PDF is refused before the text probe.
- **Magic bytes are checked twice**: in the API (skips a spawn for obvious junk) and in `preflight.check` (so the module is safe on its own).
- **`ip_hash`** = `sha256(per-process random salt + request.client.host)` (`upload.py:47`). It stores no raw IP and ignores `X-Forwarded-For`. STORY-012 replaces it.
- **`app.py` → `deps.py`:** `get_settings`/`get_store`/`SettingsDep`/`StoreDep` moved to `src/pdf_splitter/deps.py`, because `upload.py` needs them and `app.py` imports `upload.py`. `app.py` re-exports them.
- **`job_dir.mkdir()` is outside the `try`**, so a (theoretical) id collision raises instead of letting the cleanup delete another job's directory.
- Preflight stderr is never logged, because MuPDF messages can quote the path (which contains the id). Only `log_id` + the exit code are logged.

## Handoff Context for Next Session
A successful upload leaves exactly `<jobs_dir>/<id>/source.pdf` and one row `state='queued', kind='analyze'` with `pages`/`bytes`/sanitized `filename`. `upload.run_preflight` is the pattern for the worker's subprocess runner: `sys.executable -m <module>`, options first, then **`--` before any positional that can start with `-`** (job ids and the paths built from them can), `capture_output`, `stdin=DEVNULL`, `timeout`, the result on the LAST stdout line, anything else collapsed to one error code, and only `log_id` logged. `settings.jobs_dir` is always absolute now, so paths derived from it are safe to hand to argv, but keep the `--` regardless. The review also noted (not a finding here) that preflight has no memory rlimit: a 2.5 KB nested-XObject PDF reached ~790 MB RSS inside the 10 s window, so STORY-006 should apply the worker's rlimits to the preflight launch as well.
